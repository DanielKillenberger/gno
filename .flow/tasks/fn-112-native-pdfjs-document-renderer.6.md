  - **Progressive state — event-driven held-Range procedure (interception mode only; spec "Progressive state hook").** Progressive has no state card and no copy: it is proven by holding the document mid-load and asserting first-paint and pending-placeholder coexist in the same instant.
    - **Aspect oracle.** `generateLargePdf(200)` emits unrotated Letter pages, `MediaBox [0 0 612 792]` (`scripts/generate-test-fixtures.ts:369`), so every page's rendered box has width/height ratio `612 / 792 = 17 / 22 ≈ 0.772727…` at every scale and zoom. The smoke asserts `width > 0`, `height > 0`, and `Math.abs(width / height - 17 / 22) <= 0.01`. Guard the oracle against drift: read the generated file's `MediaBox` (or the generator's exported page-size constant) in the smoke process and fail loudly if it is not `[0, 0, 612, 792]` rather than silently asserting a stale ratio.
    - **Range-mode loading policy (product change, prerequisite for this whole procedure).** `src/serve/public/lib/pdf.ts` must pass `disableStream: true` (and `disableAutoFetch: true`) to `pdfjsGetDocument`, and the stale comment at `pdf.ts:158-164` describing a "fetch bridge" that "rewrites Content-Length from Content-Range" must be deleted along with `installPdfjsRangeLengthBridge` in `scripts/pdf-viewer-smoke.ts`. **Why (verified against the pinned dep, not assumed):** `node_modules/pdfjs-dist/build/pdf.mjs:12930-12959` (`validateRangeRequestCapabilities`) derives the document's total size **only** from the first response's `Content-Length`; `Content-Range` is never read, and there is no top-level `getDocument({url, length})` option in v5.7. `pdf.mjs:13055-13057` then shows the supported switch: when `disableStream` is set and ranges are supported, `PDFFetchStreamReader` cancels the full-body reader the instant headers arrive, so every byte after that arrives as an observable `Range` request. `disableAutoFetch: true` keeps pdf.js from eagerly pulling the remaining chunks, which is also the correct behavior for a windowed/virtualized viewer that only ever paints a bounded page window. Range eligibility additionally requires `Content-Length > 2 × rangeChunkSize` (64 KiB default → the generated fixture must exceed **128 KiB**; assert this in the smoke before the procedure and fail loudly otherwise) plus `Accept-Ranges: bytes` and identity `Content-Encoding`, all of which `GET /api/doc-asset` already emits (R11 / task .1).
    - **First request without a `Range` header — honest pass-through, never synthesized.** `page.route()` **only that fixture's `/api/doc-asset` URL** — no other request is intercepted. When the intercepted request carries **no** `Range` header, the handler does **not** fabricate a response: it `route.fetch()`es the real same-origin production endpoint and fulfils with that response verbatim (a genuine `200`, honest `Content-Length: <total>`, `Accept-Ranges: bytes`). Nothing is truncated, no `206` is returned without a `Range` request, and no header is rewritten. PDF.js reads the true total from that response, cancels the full reader per the policy above, and every subsequent byte becomes a holdable `Range` request. **Explicitly forbidden and superseded:** answering the `Range`-less request with a 64 KiB `206` (HTTP-incorrect — `206` without a `Range` request — and it makes PDF.js believe the file is 65 536 bytes, so ranges are disabled and only range 0 is ever requested), falsifying `Content-Length`, passing a top-level `length` to `getDocument`, and any page-side `fetch`/response bridge.
    - **Later `Range` requests are the only synthesized responses.** Serve each held request from the fixture bytes read in the smoke process (`Bun.file(largePdfPath).arrayBuffer()`) as a byte-correct `206` with `Content-Range: bytes a-b/total`, `Accept-Ranges: bytes`, and `Content-Length: b-a+1`. Holding and release timing is the only synthetic element; every byte and header is true. Record in the artifact that response *timing* was controlled, and that this run never contributes to the clean zero-non-`self` claim.
    - **Queue, do not fulfil, subsequent Range requests.** The route handler pushes each later Range request onto a queue and holds its `route` object. Expose two event-driven controls on the smoke side — `nextQueuedRange()` (a promise resolving when a request enters the queue) and `releaseNextRange()` (fulfils exactly one held request from the known bytes). No fixed sleeps anywhere in the procedure.
    - **Release only until first paint.** Release queued ranges one at a time, each time awaiting `page.waitForFunction(() => document.querySelector('[data-rendered="true"]') !== null)` (or the next queue event) under the harness's ordinary assertion timeout, until at least one page node reports `data-rendered="true"`. Then stop releasing.
    - **Guarantee a held later range.** After first paint, assert at least one later Range request is queued and still held. If virtualization has not requested one, programmatically scroll `[data-testid="pdf-page-column"]` just far enough to bring a later pending page into the IntersectionObserver window (a scroll that keeps the first painted page in the live window, so it is never evicted and first paint stays valid), then `await nextQueuedRange()` and keep that request held.
    - **Single-instant assertions** (all evaluated in one `page.evaluate` snapshot plus the held-queue count from the smoke process): `[data-testid="pdf-page-column"]` exists; `>= 1` node with `data-rendered="true"`; `>= 1` node with `data-rendered="false"`; **zero** `[data-testid^="pdf-state-"]` nodes; held later-Range count `>= 1`; and for one chosen pending (`data-rendered="false"`) node its `getBoundingClientRect()` has `width > 0`, `height > 0`, and `|width / height - 17 / 22| <= 0.01`.

It proves nothing about real network timing, streaming performance, or the zero-non-`self` posture — those claims come exclusively from the clean, non-intercepted run.

  - **P-3 product repair — deferred render admission (architecture change, added 2026-08-01 by targeted plan repair; R10).** Live evidence from this task (run15/run16, `orphans=0 doubles=0 dropped=0`) proved a genuine product miss: **200 `renderStart` vs ≤ 60**. This is not a harness artifact and is not environmental — the scheduler starts a render for every page transiting the live window, so an N-page traversal issues N starts. The repair is owned by **this task** as an amendment to task .3/.4's accepted scheduler (the same pattern already used for the range-mode loading policy in `pdf.ts`); tasks .3 and .4 stay accepted and are not reopened.
    - **Where:** `src/serve/public/hooks/use-pdf-pages.ts` only. `lib/pdf.ts`'s metrics contract gains **no** new event kind and no field change. `PdfPageView.tsx`, `PdfViewer.tsx`, `PdfToolbar.tsx`, `DocView.tsx`, the server, and every route stay untouched.
    - **Structure.** Add `SCROLL_QUIESCENCE_MS = 120` alongside `LIVE_CANVAS_CEILING` / `OVERSCAN_PAGES` — a **production behavior constant**, never harness-derived, injected, or tuned from the smoke (Sol PR6-PERF-N1). Split the current `ensureRendered` into: the existing guards, an **admission decision**, and a clearly named **ungated start path** (`startRenderAdmitted`) holding today's render body verbatim. `startRenderAdmitted` never consults the gate, so no flush can re-defer recursively. Everything downstream of admission — gen-cancel, ceiling eviction, cancel → settle → `page.cleanup()` → zero-dims, DPR/area cap, slot updates — stays byte-for-byte the accepted behavior.
    - **Admission epochs (Sol PR6-PERF-01; the boolean `startedAtGenRef` is withdrawn).** A boolean is unsafe: `ensureRendered` awaits `doc.getPage()` before `page.render()`, so a flag flipped at `renderStart` lets many concurrent callers read `false`, and a flag flipped on first entry admits exactly one page and starves the rest of the window. Instead: `epochSeqRef` is a monotonic counter bumped **synchronously** on every `docId` change and every `genId` change; opening an epoch opens its **exempt batch**. While the batch is open, every page passing the ordinary active-set guard is admitted immediately — the whole initial window, and every active page after a zoom/fit commit. The batch **closes** at the first visible-set mutation occurring *after* the batch has admitted ≥ 1 page: requiring a prior admission makes the cold-start boundary correct (there, the IO mutation is itself what makes the initial pages active), and requiring a *subsequent* mutation keeps later scroll entries out of a batch that is already serving. A closed batch never reopens; only a new epoch opens the next. **Across awaits:** admission is decided synchronously at entry, before any await, and carries an `epochSeq` token; after every await the token is revalidated against `epochSeqRef.current` alongside the existing dispose/gen/active re-checks, and a mismatch abandons the attempt without starting a render.
    - **Pending ownership and race cleanup (Sol PR6-PERF-02).** A pending entry is `{docId, genId, epochSeq, pageNumber, canvas}` — generation identity and exact canvas object included. The map **and** its timer are invalidated and cleared on every `genId` change, on `docId` change, and in `disposeAll`. The timer callback captures the `epochSeq` it was armed under and no-ops when stale; it then **atomically claims** the pending set (copy, then clear the map) before iterating, and processes entries **sequentially** so ceiling eviction cannot race. Per entry it re-checks, in order: not disposed → current `docId` and `genId` → membership in a freshly computed active set → `canvasRef.current.get(page) === entry.canvas` and `canvas.isConnected` → no existing unsettled task for that page at the current generation → live-canvas ceiling headroom. Only then does it call `startRenderAdmitted`. Entries failing any check are dropped with **no** metric event.
    - **Invariants (each maps to a budget that must not regress).** (i) Epoch exemption keeps the first window of a document and every zoom/fit commit on the immediate path — **P-1**, the progressive first-paint oracle, **P-4a** latency and **P-4b** in-flight observability. (ii) An unadmitted page produces **zero** metric events, so "exactly one terminal settle per start / zero orphans" is unchanged. (iii) Timer + map cleared on dispose and doc change → no start after `documentDestroy` (**P-6**). (iv) Admission never bypasses active-set or ceiling checks (**P-2**). (v) The gate defers only: it never cancels, never renders speculatively, and never renders off-window. (vi) At most one window's worth of starts is exempt per epoch, so P-3's single-epoch scroll stays far below 60.
